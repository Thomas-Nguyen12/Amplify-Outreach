# HelloMinds-powered fictional customer simulation in Daytona

## Purpose

`run_minds_simulation` is a deliberately **synthetic** end-to-end test of prospect qualification → research → draft generation → scripted customer response → auditing. It calls your real HelloMinds Research Mind *only* to generate a **hypothetical research assessment of fictional businesses**. No real social discovery, emails, DMs, sales, invoices, subscriptions, or outreach is performed. Minds calls may consume paid cognition/credits.

**Important safety assumption:** Configure the HelloMinds Research Mind as a read-only research agent, without any email, DM, purchase, or other externally acting tools. A prompt asking the Mind not to use tools is not a technical sandbox or permission restriction. If your Mind has autonomous integrations, disable them for this test.

All fictitious data lives in `fixtures/synthetic_customers.json`, including eight profiles with invented team sizes, sales/MRR or follower counts, customer segments, pain points, and purchasing hypotheses. Every name and domain is invented; `.example` URLs do not resolve. Do not submit these as verified facts or customer revenue.

## A. Run directly on your laptop

Prerequisites: Python 3.10+, Node.js 22+, HelloMinds Builder API key + Research Mind ID.

```bash
python -m pip install -r requirements.txt
cd bridge && npm install && cd ..
cp .env.example .env
```

Set `MINDS_ENABLED=true`, `MINDS_BUILDER_API_KEY=...`, and `MINDS_RESEARCH_MIND_ID=...` in `.env`. Never commit or share `.env`.

```bash
python -m pytest -q
python -m scripts.run_minds_simulation --max-research 2
```

Runs with up to two qualified imaginary customers, requests **real HelloMinds responses**, and writes results under `outputs/simulation/<run_id>/`. Increase to `--max-research 3` when your first live call succeeds and you understand costs. Failed requests are logged; this is a diagnostic test, not verified connectivity until you see at least one `succeeded` result.

## B. Run inside Daytona from your computer

Get a Daytona key from https://app.daytona.com/ and install Daytona SDK locally:

```bash
python -m pip install 'daytona==2.0.0a9' python-dotenv
```

Set `DAYTONA_API_KEY`, `MINDS_BUILDER_API_KEY`, and `MINDS_RESEARCH_MIND_ID` in your **local environment** (or local `.env`, which is not uploaded). Create a ZIP of the project or use the provided release archive. From an extracted project root, run:

```bash
python -m scripts.run_daytona_minds \
  --zip ../social-trend-agent-hellominds-daytona-simulation.zip \
  --max-research 2 \
  --output-zip ./daytona-minds-logs.zip
```

The runner uploads the source archive; checks dependencies and Node.js 22+; runs pytest; invokes the real Minds API against fictional fixtures; downloads the log archive; and deletes the Daytona sandbox. Your Daytona image needs Node 22+ and outbound access to the HelloMinds Builder API. Credentials are passed only as runtime environment variables, not included in the source archive. Daytona can still handle secret values as part of execution; use a restricted key and review Daytona's secret-handling configuration.

No network calls are made to simulated contacts. To test 100% offline, use `python -m scripts.run_simulation` instead.

## C. Audit and result logs

- `customers.csv` — eight fictional prospects, qualification scores and exclusion decisions
- `messages.csv` — **simulated_sent** messages (not real messages)
- `responses.csv` — **scripted** response personas, not generated by Minds and not real customer feedback
- `minds_research.csv` / `minds_research.jsonl` — responses returned by your actual HelloMinds Mind, labelled synthetic
- `events.jsonl` — detailed event log including API research attempts, results/errors, generated drafts and scripted responses
- `summary.json` — counts of synthetic leads, simulated messages, Minds research success/failure, zero live outreach and zero sales

The simulator uses a separate SQLite database (`data/simulation.sqlite3`). It does not sync into production SurrealDB. It does not verify actual demand for a £7/month daily trend-insights subscription.

## D. Common troubleshooting

- **HelloMinds is not fully configured:** check all three `MINDS_...` values; the SDK does not auto-load `.env` itself, but the Python settings layer does.
- **Cannot find module in Node:** run `npm install` inside `bridge/`.
- **Node.js too old:** install Node 22+ in your Daytona sandbox/image.
- **Reply timeout:** increase `MINDS_TIMEOUT_SECONDS` to at most 600 and inspect Minds message history before retrying; a timed-out call may still consume credits.
- **Empty research text:** verify the Mind ID and permissions and that the Mind can accept messages.
- **Requests failed:** open `minds_research.csv` and `events.jsonl`; do not assume the test succeeded just because the Python script completed.
